# Component Storybook Guide — Angular Material Adapter

This document covers what's specific to writing stories in `adapter-angular-material`. The canonical shared guide — CSF3 rules, the global Layer decorator concept, static-vs-default story conventions, composable-component patterns — lives in the `recursica` monorepo: [`packages/adapter-common/docs/COMPONENT_STORYBOOK_GUIDE.md`](https://github.com/borderux/recursica/blob/main/packages/adapter-common/docs/COMPONENT_STORYBOOK_GUIDE.md), built on top of the component implementation rules in [`COMPONENT_DEV_GUIDE.md`](./COMPONENT_DEV_GUIDE.md) — read that first. The genesis adapter, [`recursica-adapter-mantine-v8`](https://github.com/borderux/recursica-adapter-mantine-v8), is the reference implementation of that shared intent for React/Mantine.

**Read the canonical guide for shared story-writing intent, not literal API** — it's written against `@storybook/react`/CSF3-for-React, and this adapter has no `@recursica/adapter-common` dependency to import example patterns from directly (see `docs/ADAPTER_INTEGRATION_REPORT.md` Crosscutting Finding A). The sections below are this adapter's own, Angular-specific, authoritative mechanism.

## Angular / `@storybook/angular`-specific notes

- **Framework**: `@storybook/angular` (the classic, Angular-CLI-builder-based framework), **not** `@storybook/angular-vite`. Storybook's own `storybook init` auto-detects an Angular workspace as `angular-vite`, whose peer dependencies require Angular ≥21 — one major ahead of this repo's pinned Angular 20.3.16. See `docs/CREATING_AN_ADAPTER.md`'s decisions log entry "Storybook actually set up for Angular" for the full story, including the follow-on `zone.js` peer trap. Nothing about this affects how you write a story day to day, but don't "upgrade" Storybook or its Angular framework package without re-reading that entry first.
- **No separate host application project.** `angular.json`'s `storybook`/`build-storybook` architect targets attach directly to the `adapter-angular-material` library project's own `build` target — there's no thin Angular app project in this repo for Storybook to run against, and none is needed.
- **Story file naming/format**: `<kebab-name>.stories.ts` (never `.stories.tsx` — there's no JSX anywhere in this adapter), with `Meta<XComponent>`/`StoryObj<XComponent>` typed against the real component class. Every existing stub and both real components already follow this — match it.
- **Theme toggle is native Storybook, not an addon.** This repo's Storybook toolbar light/dark switch is Storybook's own built-in `globalTypes`/toolbar mechanism, configured in `.storybook/preview.ts` — **not** the third-party `storybook-dark-mode` addon the React reference adapters use. That addon is broken against this repo's pinned `@storybook/angular@9.1.20` (see `.storybook/main.ts`'s own comment for the specifics). No story needs to know about this either way — the global decorator (`StorybookThemeSyncComponent`, wired in `preview.ts`) reads the toolbar's current selection and forwards it to a real `rec-theme-provider` wrapping every story.
- **Compodoc powers the Docs panel.** `angular.json`'s `storybook`/`build-storybook` targets run `compodoc` automatically, generating `documentation.json`, which `preview.ts` feeds to `@storybook/addon-docs/angular`'s `setCompodocJson`. Write real JSDoc comments on every `@Input()` (see `layer.component.ts`/`theme-provider.component.ts` for the existing standard) — that's what populates the auto-generated Docs page and Controls panel descriptions; there's no separate `argTypes` description to hand-author for this the way a React/CSF3 story might.
- **Token/brand CSS is wired in via `angular.json`, not a `preview.ts` import.** `recursica_variables_scoped.css` is loaded through the `storybook`/`build-storybook` architect targets' own `styles` array in `angular.json`. A plain top-level `import "../../../recursica_variables_scoped.css"` inside `preview.ts` fails with a webpack "no loaders configured" error — `@storybook/angular`'s webpack config only wires up CSS loaders for stylesheets reachable through Angular's own `styles`-array build pipeline. See `theme-provider/IMPLEMENTATION_NOTES.md`'s "Token CSS wiring" section for the full failed-then-working sequence. Don't try to re-import the token CSS anywhere else.

## Storybook-only demo content

`projects/adapter-angular-material/src/storybook-demos/` (the ported Brand/Token demo stories, e.g. `color-demo`, `type-demo`, `layout-grids-demo`, plus `RecursicaJsonService`) is deliberately **not** part of the public adapter API — not exported from `public-api.ts`. `RecursicaJsonService` is an `@Injectable({ providedIn: 'root' })` singleton, the direct Angular-idiomatic replacement for the React reference Storybook setup's `RecursicaJsonProvider`/`useRecursicaJson()` React Context (Angular has no need for Context's "avoid prop drilling" mechanism — a DI singleton parses the real root `recursica_*.json` files once and makes them available anywhere they're injected). If you add another brand/token demo story, inject `RecursicaJsonService` rather than hardcoding token values, matching every existing demo's pattern.
